这篇文章由 Kieran Klaassen 撰写，详细介绍了 Every 公司（一家知名内容与软件工作室）如何利用 AI 实现一种全新的软件开发模式——**复利工程（Compound Engineering）**。

其核心思想是：**让每一次工程投入都为下一次工作降低难度，而不是随着代码量增加而让系统变得更复杂。**

以下是该文章的核心内容总结：

### 1. 核心哲学：从“负债”转为“复利”

- **传统工程（线性/负债）：** 随着功能增加，代码库变得越来越臃肿，维护成本（技术债务）随之上升。每增加一个新功能，下一次开发的难度就会增加。
    
- **复利工程（指数/复利）：** 每一单位的工作（代码、文档、工具）都应该让后续工作变得更简单。通过将经验、规则和模式“教给”系统，系统会随着时间推移变得更容易理解、修改和信任。
    

### 2. 四步闭环工作流 (The Loop)

复利工程的核心是一个不断循环的系统，让 AI Agent 在其中自主运行：

1. **计划 (Plan)：** 开发者将主要精力花在调研和编写详细的实施计划上，而不是写代码。AI Agent 阅读 Issue、研究现有代码库并合成技术方案。
    
2. **执行 (Work)：** AI Agent 根据计划编写代码并创建测试。在这个阶段，人工干预极少。
    
3. **评审 (Review)：** 开发者不只是检查代码改动，更要评审 AI 产生的“经验教训”。
    
4. **复利 (Compound)：** **这是最关键的一步。** 将本次任务中发现的 Bug、最佳实践或特殊逻辑总结为结构化文档（如 `CLAUDE.md` 或知识库），供 AI Agent 在下一次循环中参考。
    

### 3. 六大关键原则

- **品味（Taste）属于系统，而非评审：** 不要靠人工 Code Review 来把关质量，而应将判断逻辑（如架构偏好、配置规范）写入自动化检查和 Schema 中。
    
- **教给系统，而非亲自上手：** 花时间给 AI Agent 提供上下文（Context）具有指数级的长期回报，而亲手敲代码只能解决当前问题。
    
- **构建安全网，而非评审流程：** 与其通过人工卡点，不如构建验证基础设施（如强大的测试集），让 AI 可以安全地自主迭代。
    
- **环境 Agent 原生化：** 整个项目的目录结构应便于 AI Agent 导航和修改，而不是仅仅为了人类阅读。
    
- **拥抱“放手”的不适感：** 开发者需要适应从“手艺人”向“指挥家/编排者”的角色转变，忍受过程中非完美的细节以换取大规模的效率。
    
- **价值导向：** 衡量产出的标准是解决问题的数量，而不是敲击代码的行数。
    

### 4. 实际成效

Every 团队通过这套方法，目前能在多条产品线（如 Cora, Spiral 等）上保持极小规模的团队配置（通常一名开发者即可维护多个产品），因为一名“复利工程师”配合 AI 的效能相当于过去一整个工程团队。

### 总结

**复利工程**本质上是将软件工程从“代码编写”转向“系统管理”。在 AI 时代，代码是廉价且快速生成的，**“如何系统性地积累知识并反馈给 AI”** 才是决定长期开发效率的关键。
